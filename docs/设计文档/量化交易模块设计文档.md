# 量化交易模块 — 设计文档

## 背景

Argus-Invest 当前有 49 条规则定义，但仅 19 条有运行时评估器。所有规则都是单指标二值触发（如 RSI < 30 → 买入信号），没有多因子综合评分、没有回测引擎、没有组合优化、没有参数优化。30 条行为/仓位/移动止损规则仅存储从未执行。量化交易模块从零重新设计，不再在原有代码基础上修补。

## 设计目标

1. **多因子综合评分引擎** — 不再是单指标二值触发
2. **策略回测框架** — 验证策略历史表现
3. **组合层面优化** — 相关性矩阵、风险平价、凯利公式
4. **参数优化** — 网格搜索 / 步进优化
5. **策略 DSL** — 用户可自定义量化规则
6. **实时信号与前端可视化** — ECharts 图表、量化中心页面

## 核心架构

```
┌─────────────────────────────────────────────────────────────┐
│                     Quant Engine                             │
├─────────────────────────────────────────────────────────────┤
│  Strategy DSL  │  Signal Engine  │  Backtester  │  Optimizer │
├─────────────────────────────────────────────────────────────┤

```

## 模块一：统一数据管道 (Data Pipeline)

**问题**：原有系统 4 个独立数据源（AkShare、Tushare、腾讯财经、东方财富），API 格式各异，无统一接口。

**设计**：

```
backend/app/quant/data/
├── pipeline.py          # 数据管线主入口
├── providers/
│   ├── base.py          # BaseDataProvider 抽象类
│   ├── akshare.py       # AkShare 适配器 (priority=30)
│   ├── tencent.py       # 腾讯财经适配器 (priority=20)
│   └── tushare.py       # Tushare 适配器 (priority=10)
├── schema.py            # 统一数据 Schema（OHLCV 列名常量、normalize_ticker）
└── cache.py             # 本地 Parquet 缓存 + 增量更新
```

**统一 OHLCV Schema**：`ticker, date, open, high, low, close, volume, amount, turnover_rate, pre_close, change_pct`

**关键决策**：
- Provider 按 priority 排序，高优先级优先，失败自动 fallback
- 日线数据按 ticker 缓存为独立 Parquet 文件（`data/market/{TICKER}.parquet`）
- `DataPipeline` 是模块单例，通过 `get_pipeline()` 获取

## 模块二：因子计算引擎 (Factor Engine)

**问题**：原有 `monitor_service.py:calculate_indicators()` 散落 14 个指标计算，无分类、无可复用因子库。

**设计**：

```
backend/app/quant/factors/
├── base.py              # BaseFactor 抽象类 + FactorResult
├── registry.py          # FactorRegistry 装饰器注册表
├── trend/               # 趋势类 (10 factors)
│   ├── ma.py            # ma_5, ma_20, ma_60, ma_120, ma_250, ema_12, ema_26, trend_strength, ma_bull, ma_bear
│   └── macd.py          # macd, macd_signal, macd_hist, macd_golden_cross
├── momentum/            # 动量类 (6 factors)
│   ├── rsi.py           # rsi_6, rsi_14, rsi_28
│   └── kdj.py           # kdj_k, kdj_d, kdj_j
├── volatility/          # 波动类 (6 factors)
│   ├── bollinger.py     # boll_middle, boll_upper, boll_lower, boll_width, boll_position
│   └── atr.py           # atr_14
├── volume/              # 量价类 (3 factors)
│   └── volume_ratio.py  # volume_ratio, volume_ma_20, obv
└── composite/           # 复合因子
    └── score.py         # zscore, percentile_rank, weighted_score, ic_analysis
```

**因子注册模式**：
```python
@FactorRegistry.register("rsi_14")
class RSIFactor(BaseFactor):
    name = "rsi_14"
    category = "momentum"
    params = {"period": 14}

    def compute(self, df: pd.DataFrame) -> pd.Series:
        ...
```

**因子标准化**：`FactorRegistry.compute_all(df)` 批量计算，`zscore()` / `percentile_rank()` 标准化，IC/IR 分析支持。

## 模块三：综合信号引擎 (Signal Engine)

**问题**：原有规则是单因子二值触发，无法表达"RSI 超卖 AND 布林下轨 AND 放量"这类多条件组合。

**设计**：

```
backend/app/quant/signals/
├── engine.py            # SignalEngine 核心 + Strategy 数据类
├── rule.py              # DSL 解析器（递归下降，手写 Parser）
├── scorer.py            # SignalScorer — 多因子加权评分
├── filters.py           # 过滤器（涨跌停、零成交量、超低价）
└── presets.py           # 5 个预置策略
```

**DSL 语法**：
```
signal: oversold_bounce
condition: rsi_14 < 35 AND boll_position < 0.15 AND volume_ratio > 1.0
score: rsi_14 * 0.3 + boll_position * 0.4 + volume_ratio * 0.3
threshold: 0.55
action: buy
```

支持运算符：`>`, `<`, `>=`, `<=`, `==`, `!=`, `cross_above`, `cross_below`, `AND`, `OR`, `NOT`

**5 个预置策略**：

| 策略名 | 描述 |
|--------|------|
| `ma_golden_cross` | MA5 上穿 MA20 + 放量确认 |
| `macd_golden_cross` | MACD 金叉 + 动量确认 |
| `rsi_oversold_bounce` | RSI 超卖 + 布林下轨反弹 |
| `boll_breakout` | 放量突破布林上轨 |
| `trend_following` | 多头排列 + 回调至 MA20 |

## 模块四：策略回测引擎 (Backtester)

**问题**：原系统完全没有回测能力，无法验证任何规则的有效性。

**设计**：

```
backend/app/quant/backtest/
├── engine.py            # BacktestEngine — 事件驱动回测循环
├── broker.py            # Broker — 模拟券商（佣金/印花税/滑点/T+1）
├── portfolio.py         # BacktestPortfolio — 回测组合管理
├── recorder.py          # TradeRecorder — 交易记录
└── reporter.py          # BacktestReporter — 报告生成
```

**回测流程**：
```
for each trading day:
  1. 更新持仓市值
  2. 执行 T+1 订单（上一日信号产生的订单）
  3. 计算因子、评估今日信号
  4. 根据信号生成新订单（次日执行）
  5. 记录持仓快照
```

**模拟券商规则**：
- 佣金 0.03%（最低 5 元）、印花税 0.1%（卖出单向）、滑点 0.1%
- T+1 交易制度、最小交易单位 100 股
- 涨跌停板限制有效

**回测指标**：累计收益、年化收益、夏普比率、索提诺比率、最大回撤、卡玛比率、Alpha、Beta、胜率、盈亏比、平均持仓天数

## 模块五：组合优化引擎 (Portfolio Optimizer)

**问题**：原系统只做个股分析，没有组合层面的风险和收益优化。

**设计**：

```
backend/app/quant/portfolio/
├── optimizer.py         # PortfolioOptimizer — 三种优化方法
└── methods/             # 预留扩展
```

**三种优化方法**：

1. **均值-方差（马科维茨）**：`scipy.optimize.minimize` 求最优权重，约束单票 ≤ 20%
2. **风险平价**：等风险贡献，minimize `Σ(RC_i - 1/n)²`
3. **凯利公式**：`f = (bp - q) / b`，支持分数凯利

额外功能：有效前沿散点生成、相关性矩阵

## 模块六：参数优化引擎 (Parameter Optimizer)

**问题**：原有参数（如 RSI 周期 14）都是硬编码。

**设计**：

```
backend/app/quant/optimize/
├── engine.py            # GridSearchOptimizer — 网格搜索 + 步进优化
└── methods/             # 预留：贝叶斯优化扩展
```

**步进优化（Walk-Forward）**：
```
1. In-Sample (24个月) 网格搜索最优参数
2. Out-of-Sample (6个月) 验证
3. 窗口向前滚动，重复
4. 汇总所有 OOS 表现 → 评估策略稳健性
```

## 技术选型

| 组件 | 选型 | 原因 |
|------|------|------|
| 数值计算 | pandas + numpy | 已有依赖 |
| 优化求解 | scipy.optimize | 轻量，二次规划 |
| DSL 解析 | 手写递归下降 Parser | 语法简单，零依赖 |
| 回测引擎 | 自研事件驱动 | 定制化需求 |
| 前端图表 | ECharts + vue-echarts | 功能完整 |
| 定时任务 | threading.Timer | 进程内调度 |
